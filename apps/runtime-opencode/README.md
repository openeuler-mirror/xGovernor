# OpenCode runtime

This crate implements `agent_runtime_protocol::AgentRuntime` for **OpenCode 2.3.0 only**. Supply an absolute executable path to `OpenCodeRuntime::new`, an explicit OpenAI-compatible endpoint, model and credential in `RuntimeStartRequest.llm`, and the sandbox's operation backend in `RuntimeExecutionContext`. Unsupported model protocol/capability overrides are rejected.

Each runtime session owns a loopback HTTP server, private configuration and database. The bundled V2 plugin redirects `shell`, `read`, `write`, `edit`, `glob` and `grep` to the supplied operation backend. Commands run in the sandbox; file paths resolve there. Background shell calls, other tools, project configuration, MCP, skills, browser, LSP, formatters, dynamic provider installation and unapproved plugins are disabled. Hosts with `/etc/opencode` are rejected because the CLI cannot disable that configuration source. Install the official executable and its built-in provider support before starting sessions; the adapter does not install packages.

The model key stays in the Rust adapter. The trusted plugin holds a temporary credential for a local model proxy and adds it only to proxy HTTP headers. Provider configuration contains a non-secret placeholder. Child processes start with a private HOME/XDG tree and a cleared environment. Sandbox operations receive no adapter credentials. OpenCode stdout/stderr are bounded, checked for credentials, and discarded after extracting the listen announcement. Startup checks the actual plugin inventory, authentication, listener and private paths; unknown active plugins fail startup. The bridge handshake occurs inside plugin setup, before OpenCode publishes its active inventory; startup waits for both signals, including after state import. Failed activation or process exit fails startup immediately; incomplete activation has a 30-second deadline and the server is terminated before returning an error. Runtime errors retain the HTTP method, API path, status or timeout/connection category without credential-bearing transport details.

Each user turn defaults to **30 model requests** (up to 29 steps with tools followed by a text summary) and **2,048 output tokens per model request**, including the provider's reasoning allowance. This leaves room for SWE code inspection, editing, focused checks and follow-up fixes across tens of steps while bounding runaway loops; larger tasks can opt into a higher bound. Set `RuntimeStartRequest.ext["opencode"]` to `{"steps": 40, "output_tokens": 4096, "turn_timeout_s": 1800}` to override these positive integer limits at runtime startup. Unknown fields or zero limits are rejected. The selected `build` agent uses OpenCode 2.3.0's native `steps` setting and its active value is checked at startup; the model output limit uses the provider model's `limit.output`. The model proxy also rejects requests beyond the step allowance, preventing output-limit continuations from extending the turn. Reaching the bound reports `Completed` with `MaxTurns` and the recorded usage; it does not poison the session. New user input resets the allowance. Each turn also defaults to a **1,800-second wall-clock budget**, including model rate-limit backoff. Thirty minutes allows the 30-request allowance to remain useful under shared model throttling while bounding stalled turns; `turn_timeout_s` overrides it at startup. The runtime turn protocol has no deadline field. Reaching the time budget interrupts and drains current work, returns `Completed` with `BudgetExhausted`, and keeps completed sandbox writes, exportable conversation state and actual provider usage. It does not poison the session; interrupt, cleanup or incomplete metering errors still fail closed. The wall-clock budget covers the drive; interruption, cleanup and usage draining can take additional bounded time. This bounds a turn's work, not the run's total token budget: repeated input tokens still count, and run-level admission remains the caller's responsibility.

A turn streams text and tool activity through the native HTTP event stream. It fences operations before reporting a terminal event and waits for backend cleanup. Cancellation drains in-flight file operations and interrupts the agent while keeping the control plane alive for terminal state export. Releasing the session terminates its server process group after a grace period. Failed or cancelled sessions require replacement. Model responses are drained independently of the agent connection so actual provider usage remains available on failure or timeout; no request-count estimates are used. State export has a separate 60-second timeout. User interaction requests immediately fail the turn. Checkpoint export requires an idle session. Restore through `RuntimeStartRequest.state` creates a new server, database, session identity and operation binding; in-place state replacement is unsupported.

`continuation(runtime_id)` returns the selected live server URL, OpenCode session ID and its HTTP password. This is a privileged control-plane handle: retain the runtime and its sandbox until the caller releases the selected branch, and never serialize or log the handle. A later process resumes from the immutable exported state and newly supplied model credentials.

The two ignored `controlled_*` tests check the actual active plugins, model request tool names, authenticated listener, private paths and credential-free logs on the pinned executable. The ignored `e2b_tools_credentials_and_parallel_restore` test requires `OPENCODE_EXECUTABLE`, `E2B_API_KEY`, `MODEL_API_KEY`, `XGOVERNOR_LLM_API_BASE` and `DEEPSEEK_LLM_MODEL`. It provisions bounded-lived E2B resources and deletes them after the run. The ordinary binding test requires no external services. The ignored `restored_session_waits_for_plugin_activation_before_turn` test delays setup after the handshake, restores a snapshot into a fresh server, and checks a redirected tool turn and subsequent export. The ignored `turn_time_budget_keeps_candidate_state_and_usage` test uses a 180-second override to check a completed time budget, preserved sandbox edits, state export and actual usage. The ignored `turn_step_limit_completes_with_usage` test uses the pinned executable and real model with a two-step override to check bounded tool execution, the terminal reason and metering.

Known limitation: OpenCode 2.3.0 cannot disable its PTY capability. PTY is unreachable from the model and sandbox because only the six redirected tools are visible, other execution plugins are disabled and checked, and the HTTP control plane listens only on loopback with a fresh per-session password. The adapter never calls PTY APIs. Temporary files and data live under the private session directory. A privileged continuation handle grants control-plane access and must remain outside model and sandbox input.
