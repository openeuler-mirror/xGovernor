# Language-neutral testing

The task may use any language or stack. Choose the natural verification method for
the repository:

- Python: inline checks with `python3 - <<'PY' ... PY` (import the product and
  assert) or `python3 -c '...'`.
- Node.js: `node -e '...'` or a heredoc script.
- Java: write a temporary test class under `/tmp`, compile with `javac`, run it.
- Go: `go test ./...` or a small `go run` check.
- C/C++: compile with `gcc`/`g++`, run the produced binary, and assert output or
  exit code.
- Anything else already installed: shell out to the appropriate command.

Do not assume pytest or any single framework. You own the exact command(s).

- Read the task/goal first, then inspect the repository as little as needed to
  learn the public interface you must exercise.

- Add discriminating cases where reasonable: empty/boundary inputs, error paths,

  fail at least one check.

# Output and capture discipline

- For each check, print exactly one line:
  `PASS <name>` when it passes, or
  `FAIL <name> <short reason>` when it fails.
- Exit 0 only when every check passes; otherwise exit 1.
- Do NOT use `set -e`. Each check must run to completion and print its own
  PASS/FAIL line even when the product fails.
- When you run the product or a test toolchain, capture or redirect its output (for
  example `out=$(cmd 2>&1)` or write its output to a file under `/tmp` and then
  assert on that). Only the PASS/FAIL lines that YOU print may reach stdout. Never
  let product output or a tool's own "PASS"/"FAIL" lines leak into stdout.
